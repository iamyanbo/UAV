Language-conditioned JEPA world models for drones

genuinely open gap

JEPA predicts future latent representations instead of reconstructing pixels — cheaper and faster than the flow-matching/diffusion approach WorldFly uses. The three adjacent pieces already exist separately; the combination doesn't.

Prior art & closest existing work
  • SkyJEPA (arXiv:2606.23444, incl. LeCun) — state-history JEPA for quadrotors, zero-shot sim-to-real via MPPI. No language input at all.
  • V-JEPA 2 / V-JEPA 2-AC (arXiv:2506.09985, Meta) — 1.2B params, plans in ~16s/action (16× faster than diffusion baseline Cosmos). Manipulation only, image-goal only — authors flag language conditioning as future work.
  • Closest match: "Policy-Guided World Model Planning for Language-Conditioned Visual Navigation" (arXiv:2603.25981) — JEPA-style + language, but ground robots only, explicitly contrasted against aerial platforms.
  • WorldFly / WorldVLN / ImagineUAV all pair language with a world model — but via generative/diffusion/flow-matching, never JEPA's non-generative objective. ImagineUAV even name-checks the JEPA alternative and doesn't use it.
Technical risks
⚠JEPA is documented to suffer representational collapse, requiring regularization tricks (SigReg, EMA target encoders).
⚠Reduced sensitivity to fine-grained action differences — a problem for precise attitude/thrust control specifically (flagged for manipulation by CAPE, arXiv:2606.07304, likely extends to flight).
⚠Data hunger — V-JEPA 2 pretrained on 1M+ hours of video. No aerial egocentric footage exists at that scale; needs a SkyJEPA-style simulated pipeline plus a new language-labeling layer.
⚠Naive long-horizon planning collapses under CEM/MPC — FF-JEPA (arXiv:2606.09311) built a hierarchical fix worth borrowing.
Scoped project sketch
  • Extend SkyJEPA's state-history latent-dynamics architecture with a text encoder feeding a subgoal-conditioning mechanism.
  • Model the conditioning on FF-JEPA's action-free latent planner, not V-JEPA 2-AC's brittle explicit image-goal requirement.
  • Train on SkyJEPA-style simulated data augmented with auto-generated language annotations.
  • Benchmark against three baselines: SkyJEPA (no language), WorldFly (generative, has language), and a naive VLM+classical-planner pipeline.
  • Report both task success and control-loop latency — latency is precisely what motivates JEPA over the generative alternative.

Gaussian-native policies & world models for UAVs

genuinely open, aerial-specific

Feed Gaussian primitives directly into a policy or predict future Gaussian states — instead of only rendering images from a splat. This pattern is already a named subfield. It has just never left the ground.

Prior art & closest existing work
  • GST-VLA (arXiv:2603.09079) — tokenizes Gaussian position/covariance/SH coefficients directly into a VLA transformer, bypassing rendering. Tabletop manipulation only.
  • ManiGaussian (arXiv:2403.08321, ECCV 2024) — predicts actions from Gaussian embedding-space features, +13.1% success across 10 RLBench tasks.
  • "Gaussian world models" are now a named pattern: GWM (ICCV 2025), GAF (arXiv:2506.14135) predict future 4D Gaussian states for manipulation; GEM (arXiv:2605.17682) applies it to driving occupancy forecasting.
  • Every UAV-3DGS system found (SOUS VIDE/FiGS, GRaD-Nav, Splat-Nav, ActiveGS, VISTA, FalconGym 2.0) uses 3DGS only as a differentiable simulator/map — never as direct policy input or predictive substrate.
Technical risks
⚠3DGS compression is mature for storage/render FPS (LightGaussian: 15× smaller, 139→215 FPS) — but no paper benchmarks compressed-Gaussian-to-policy inference latency. "Cheap enough for a control loop" is an extrapolation, not a validated result.
⚠Risk of being under-differentiated from simply porting ManiGaussian/GWM to a new domain, unless paired with a genuinely new predictive objective.
Scoped project sketch
  • Build a compressed/pooled Gaussian scene descriptor: PUP 3D-GS-style uncertainty pruning + GaussianPrediction-style motion distillation (cuts dynamic nodes from hundreds of thousands to a few hundred).
  • Feed it as direct input to a lightweight UAV navigation policy.
  • Benchmark against (a) a standard image-based VLA baseline, and (b) ManiGaussian's approach ported to a navigation task.
  • Report task success and the previously-unmeasured Gaussian-to-policy forward-pass latency at flight-control rates.

Matryoshka-style VLM/VLA unification

open but risky

Train one nested model instead of gluing a slow VLM planner to a fast VLA controller. Unclaimed at the technique level — but the closest analog domain shows the underlying problem (catastrophic forgetting) is only partially solved, even by frontier labs.

Prior art & closest existing work
  • Matryoshka Representation Learning (arXiv:2205.13147) and MatFormer (arXiv:2310.07707) — one 850M-param run yields 200+ extractable submodels, each beating independently trained models of the same size. Already reached VLMs: M3 (arXiv:2405.17430), MQT-LLaVA (arXiv:2405.19315).
  • Targeted search for "Matryoshka VLA" / "elastic VLA" / "MatFormer robot": nothing found. The pattern has never touched an action-generation head, on any robot.
  • Distinct from VLA distillation (already a small niche): VLA-AD compresses OpenVLA 44× to 158M params with a 0.27% performance gap (arXiv:2605.16241) — but that's a second standalone student model, not one artifact serving both roles.
  • Only clean shared-weight precedent: FiS-VLA (arXiv:2506.01953) — fast System 1 literally = the final blocks of the same network as slow System 2.
  • Closest UAV precedent: LiteVLA-H (arXiv:2605.00884) — one 256M model serves both a 19.74Hz fast mode and a slower semantic mode, but via decoding-length elasticity, not weight nesting.
Technical risks
⚠VLM2VLA (arXiv:2509.22195): OpenVLA scores 0 on most of 12 VQA benchmarks after action fine-tuning — severe catastrophic forgetting.
⚠π0.5's Knowledge Insulation (arXiv:2504.16054), built specifically to prevent this, still shows major collapse on some benchmarks (MMB-cn 0.3, RealWorldQA 2.7). Authors' own conclusion: "co-training is not a guaranteed solution to catastrophic forgetting."
⚠A null result (nesting doesn't help) is a live possibility that would need honest reporting, not just a positive result to chase.
Scoped project sketch
  • Train one UAV VLA with MatFormer-style nested FFN blocks so the smallest extractable submodel is the fast reactive controller, and the full model is the slow semantic planner.
  • Borrow a knowledge-insulation-style gradient-isolation scheme from π0.5 to protect the smallest submodel's control competence from the largest submodel's language objective.
  • Compare against CognitiveDrone-R1's glued two-network baseline (arXiv:2503.01378) and against LiteVLA-H.
  • Report task success at each nesting level and VQA/semantic retention — directly testing whether nesting mitigates or worsens the VLM2VLA-style forgetting pattern.

JEV for real-time UAV decisions

not viable as a foundation

TypeSafe AI's "System One" model, launched Sept 15–16, 2026. Interesting as a trend signal, not as infrastructure to build a thesis on.

What it actually is & why it falls short
  • No independent technical paper — only a company blog post and press coverage. "No architecture paper, no public leaderboard scores... for independent testing" (Hacker News digest).
  • Outputs only Choice (categorical), Score (ordinal), or Noul (single 0–1 value) — cannot emit continuous multi-DoF flight commands directly.
  • Cloud/API-only ($0.042/M tokens, no open weights) — the reported 70–500ms latency is a network round-trip, which undercuts any "onboard real-time" framing.
  • Self-labeled "0% hallucination" claim is admitted by TypeSafe itself to be "not empirical."
  • One existing demo: jev-drone (independent GitHub hobbyist project) — Jev as an advisory 2.5Hz layer over a conventional flight controller, MuJoCo sim only. Author's own words: "a single 65s run, not a seed-matched average," and the harder tunnel test is "not a working system."
  • The underlying concept — fast, parallel, calibrated discrete decisions — already has prior art: dual-process "System 1/2" navigation (arXiv:2601.21506), discretized-action driving (DriveAction, arXiv:2506.05667), calibration-aware VLA action selection (CALMM-Drive, ReconVLA).

Neither literature has combined them for aerial navigation.
