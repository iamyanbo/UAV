# UAV research contract — open research revision v6

The goal is substantive, implementable research in UAV navigation, tracking or exploration, informed by the original ideas, literature and primary method code. The agent chooses the research question, architecture, data, simulator and evaluation. There is no mandatory model family, gym, benchmark, fixed paper list or preset experiment count. The Handoff is motivation, not a blueprint.

Start from the primary use case defined in the mission: moving quadrotor waypoint navigation through cluttered, partially observed 3D scenes under an explicit sensor and latency budget. Tracking and exploration are not part of the next claim. Explain the closest prior work at the level of its actual computation and training, then develop a mechanism or architecture that goes beyond a renamed standard component, heuristic, or assembly of familiar modules. Build and run it; literature-only proposals and tiny proxies are not the terminal product. A useful reproduction or engineering capability can be checkpointed before the new claim is fully tested. Keep the program's code, model weights, data and next research step across tasks.

Choose evidence that can answer the claim. Before another model ablation, establish an environment/data path that actually contains the use-case difficulty: continuous 3D motion, meaningful geometry and appearance, occlusion, collision/braking consequences, route alternatives, and an explicit camera/IMU/depth and inference-age envelope. Prefer an established research environment or a public real-scene reconstruction; if using real-to-sim, quantify what is retained and what is synthetic. Compare relevant strong methods on matched information and resources, and examine failure, generalization, latency, leakage and sim-to-real assumptions where they matter. A simulator library is not itself a model baseline. A quick diagnostic may kill a clearly weak mechanism but cannot refute an entire model family. Report uncertainty and scope; no metric or artifact declaration alone proves novelty or transfer.

For an implementation handoff, keep a readable method account, runnable code, raw measurements, trained weights when applicable, and a continuation note. `MODEL_IMPLEMENTATION.json` tells the runtime where these files are so it can preserve them across tasks, including files outside Git. It may live in the project subfolder. Paths and field names are for artifact transfer, not a scientific rubric. Run a meaningful executable check before checkpointing reusable progress.

The lead can record a bounded intermediate result and checkpoint it without a second formal audit handoff. A strong supported/refuted conclusion still requires critical review of actual code, data, baselines and behavior; a manifest never proves it. Preserve negative results only at the exact tested scope. An audit is useful when it adds scientific judgment, not when it repeats a receipt.

The current five-scene ranking-loss and Stage-3 prototypes are engineering diagnostics, not a UAV-navigation advance: their procedural geometry, privileged candidate teacher, limited action set and weak route behavior do not establish visual navigation. Do not promote their proposed extra episodes or further loss ablations into the research agenda. The immediate task is environment/data foundation for the specific moving-waypoint use case. It must produce a visible flight example, route/collision/occlusion/latency measurements, and a documented sensor and dynamics interface. Only after that foundation is usable should the program choose a consequential residual failure and design, train and compare an integrated method. If an established environment or real-scene asset cannot run locally, state the exact constraint and implement the narrowest faithful adapter or data path; do not silently substitute a toy world and claim progress.

Use configured local Spark/Qwen research inference and the 60% local VRAM guard. Do not use a physical aircraft or incur new spending. Primary sources remain accessible; older generated conclusions are archived and must be read at their original scope.
